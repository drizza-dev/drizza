Conectar o GitHub

Preencha os cards de pull requests com as PRs abertas que aguardam sua revisão e as que você abriu.

O que o Drizza lê

Cada sync faz duas buscas na API de busca do GitHub, com as suas próprias credenciais, direto do processo local:

  • Revisões pedidas: is:pr is:open archived:false review-requested:@me
  • Suas pull requests: is:pr is:open archived:false author:@me

Os resultados ficam em cache no banco SQLite local. Um sync só começa quando você clica em Sync Now no dashboard.

Como o Drizza encontra um token

No início de cada sync, o Drizza procura um token nesta ordem:

  1. A saída de gh auth token, do GitHub CLI.
  2. A variável de ambiente DRIZZA_GITHUB_TOKEN do processo do Drizza.

Se o GitHub CLI devolver um token, a DRIZZA_GITHUB_TOKEN não é usada. Para sincronizar com um token de acesso pessoal, rode o Drizza num ambiente em que gh auth token não devolva token.

Recomendado: o GitHub CLI

Instale o GitHub CLI e faça login:

gh auth login

Confirme que há um token disponível para o mesmo usuário que roda o Drizza:

gh auth status

Depois inicie o Drizza como descrito em Rodar localmente, abra o dashboard e clique em Sync Now. Depois de um sync bem-sucedido, a fonte GitHub mostra Sync via gh.

Alternativa: um token de acesso pessoal fine-grained

Se você não usa o GitHub CLI, crie um token de acesso pessoal fine-grained e entregue-o ao Drizza pela DRIZZA_GITHUB_TOKEN.

  1. Em Resource owner, escolha a conta ou a organização dona dos repositórios privados que você quer ver.
  2. Em Repository access, selecione esses repositórios, ou todos os repositórios desse dono.
  3. Em Repository permissions, defina Pull requests como Read-only. O GitHub adiciona Metadata como somente leitura automaticamente. Não conceda permissão de escrita; o Drizza só lê.
  4. Gere o token e mantenha-o fora de arquivos versionados ou compartilhados.

Defina a variável no shell que inicia o Drizza, para que só esse processo a receba:

export DRIZZA_GITHUB_TOKEN=<seu-token>

Inicie o Drizza nesse mesmo shell e clique em Sync Now. Depois de um sync bem-sucedido, a fonte GitHub mostra Sync via PAT.

Sobre a permissão mínima. A documentação do GitHub diz que o endpoint de busca não exige nenhuma permissão fine-grained específica e que ele devolve só os recursos que o token acessa. PRs públicas sempre aparecem. PRs privadas exigem que o repositório esteja no acesso do token; Pull requests: Read-only é a escolha conservadora para isso. Ainda não foi verificado se Metadata sozinha basta para PRs privadas aparecerem na busca.

Para onde vai o token

  • O Drizza lê o token no início de cada sync e o envia só para api.github.com.
  • O banco SQLite registra só a origem do token (gh ou env), nunca o valor.
  • O valor do token não é gravado em logs, em respostas da API nem no dashboard.

Para revogar o acesso, saia com gh auth logout, ou apague o token de acesso pessoal nas configurações do GitHub e remova a DRIZZA_GITHUB_TOKEN.

Limites conhecidos

  • 100 pull requests por card. Cada busca lê uma única página de até 100 resultados, então um card mostra no máximo 100 PRs. O que passar disso fica de fora, sem aviso no dashboard.
  • Resultados parciais. Quando o GitHub informa que uma busca estourou o tempo (incomplete_results), o Drizza mantém o cache anterior daquele card e o dashboard mostra um sync parcial.
  • Um dono por token de acesso pessoal. Um token fine-grained só alcança recursos privados do seu resource owner. PRs privadas de outros donos não aparecem. O token do GitHub CLI não tem esse limite.
  • Limite de buscas. O GitHub permite um número limitado de buscas autenticadas por minuto, e cada sync usa duas. Quando o limite é atingido, o sync falha e o dashboard mostra quando tentar de novo.

Solução de problemas

O dashboard diz que o token está ausente

A fonte GitHub mostra Token ausente, e uma mensagem de status explica o que fazer. Nem gh auth token nem DRIZZA_GITHUB_TOKEN devolveram token para o processo do Drizza. Rode gh auth status com o mesmo usuário, ou confirme que a variável foi exportada no shell que iniciou o Drizza, Se você exportou a variável depois de iniciar o Drizza, reinicie-o a partir desse shell.

O GitHub CLI não consegue ler o keychain

Por SSH ou em outras sessões que não são de login, o GitHub CLI pode não conseguir ler um token guardado no keychain do sistema. O Drizza detecta isso e sugere o comando abaixo. Faça login de novo com armazenamento em arquivo:

gh auth login --insecure-storage

Isso guarda o token no arquivo de configuração do GitHub CLI em vez do keychain. Outra opção é usar a DRIZZA_GITHUB_TOKEN.

O GitHub recusou o token ou a busca

Confira se o token não expirou, se os repositórios estão no acesso dele e se ele tem Pull requests: Read-only. Se o resource owner for uma organização que exige aprovação, o token fica pendente e só lê recursos públicos até alguém dono da organização aprová-lo. Organizações com SAML single sign-on também exigem que você autorize o token.

Algumas pull requests não aparecem

Confira o acesso a repositórios e o resource owner do token, e o limite de 100 resultados descrito acima.
