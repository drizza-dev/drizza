Run Drizza locally

Start the local Drizza app and understand how it uses your machine.

Requirements

Use Node.js 22.13+ or 23.4+ (the range ^22.13.0 || >=23.4.0). Drizza uses Node's built-in SQLite support, so use a release in the supported range. npx comes with Node.js.

Start Drizza

Drizza is published on npm as drizza. Start it with npx, without cloning or building anything:

npx drizza

Drizza binds to 127.0.0.1 and listens on port 4340 by default. Open http://127.0.0.1:4340/ in your browser. On start it also prints the local MCP endpoint and the commands to register it in Claude Code and Codex; the MCP token stays in its file and is never printed.

Options

  • --port <port> listens on another port, from 1 to 65535.
  • --db <path> keeps the SQLite database at another path. A leading ~ expands to your home directory.
npx drizza --port 4341 --db ~/drizza-data/drizza.db

Building from source. To run Drizza from a clone of the repository, for example to test a change, see Contributing.

Local data

Drizza keeps its data in ~/.drizza. The SQLite database lives at ~/.drizza/drizza.db; Drizza creates it on the first run and keeps it on your machine. With --db, the database and the MCP token file live in the directory of that path instead.

Back up your data. To preserve local Drizza data, include the database file in your own backup plan. Keep a copy only in a location you trust.

Security and tokens

  • The local server binds to 127.0.0.1, so it is not exposed to other devices on your network.
  • The GitHub integration uses your credentials from the local process and sends requests directly to GitHub. The SQLite database records only where the token came from, never its value. See Connect GitHub.
  • The MCP token for agents is created on the first start in ~/.drizza/mcp-token, readable only by your user. To find, rotate, or revoke it, see the MCP guide.

Integrations

To fill the pull request cards, follow Connect GitHub. For agents, see the MCP guide. The Slack integration is coming soon.
