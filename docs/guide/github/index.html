Open-source guide

Connect GitHub

Fill the pull request cards with the open pull requests that wait for your review and the ones you authored.

What Drizza reads

Each sync runs two searches against the GitHub search API, using your own credentials, directly from the local process:

  • Review requests: is:pr is:open archived:false review-requested:@me
  • Your pull requests: is:pr is:open archived:false author:@me

The results are cached in the local SQLite database. A sync starts only when you click Sync Now in the dashboard.

How Drizza finds a token

At the start of every sync, Drizza looks for a token in this order:

  1. The output of gh auth token, from the GitHub CLI.
  2. The DRIZZA_GITHUB_TOKEN environment variable of the Drizza process.

If the GitHub CLI returns a token, DRIZZA_GITHUB_TOKEN is not used. To sync with a personal access token instead, run Drizza in an environment where gh auth token does not return a token.

Recommended: the GitHub CLI

Install the GitHub CLI and sign in:

gh auth login

Confirm that a token is available to the same user that runs Drizza:

gh auth status

Then start Drizza as described in Run locally, open the dashboard, and click Sync Now. After a successful sync, the GitHub source shows Sync via gh.

Alternative: a fine-grained personal access token

If you do not use the GitHub CLI, create a fine-grained personal access token and expose it to Drizza through DRIZZA_GITHUB_TOKEN.

  1. Under Resource owner, pick the account or organization that owns the private repositories you want to see.
  2. Under Repository access, select those repositories, or all repositories of that owner.
  3. Under Repository permissions, set Pull requests to Read-only. GitHub adds Metadata as read-only automatically. Do not grant write permissions; Drizza only reads.
  4. Generate the token and keep it out of files that are committed or shared.

Set the variable in the shell that starts Drizza, so only that process receives it:

export DRIZZA_GITHUB_TOKEN=<your-token>

Start Drizza from the same shell and click Sync Now. After a successful sync, the GitHub source shows Sync via PAT.

About the minimum permission. GitHub documents the search endpoint as requiring no specific fine-grained permission, and it returns only the resources the token can access. Public pull requests are always visible. Private pull requests need the repository in the token's repository access; Pull requests: Read-only is the conservative choice for that. Whether Metadata alone is enough for private pull requests to appear in search has not been verified.

Where the token goes

  • Drizza reads the token at the start of each sync and sends it only to api.github.com.
  • The SQLite database records only where the token came from (gh or env), never its value.
  • The token value is not written to logs, API responses, or the dashboard.

To revoke access, sign out with gh auth logout, or delete the personal access token in your GitHub settings and unset DRIZZA_GITHUB_TOKEN.

Known limits

  • 1,000 pull requests per card. Each search reads pages of 100 results until it has them all, up to the 1,000 results the GitHub search API returns. Beyond that, the dashboard shows a partial sync. Drizza 0.1.0 reads a single page, so a card shows at most 100 pull requests there.
  • Partial results. When GitHub reports that a search timed out (incomplete_results), Drizza keeps the previous cache for that card and the dashboard shows a partial sync.
  • One owner per personal access token. A fine-grained token only reaches private resources of its resource owner. Private pull requests from other owners do not appear. The GitHub CLI token does not have this limit.
  • Search rate limit. GitHub allows a limited number of authenticated search requests per minute, and each sync uses at least two (one per card, plus one per extra page of 100 results). When the limit is reached, the sync fails and the dashboard shows when to try again.

Troubleshooting

The dashboard says the token is missing

The dashboard interface is in Brazilian Portuguese: the GitHub source shows Token ausente, and a status message explains what to do. Neither gh auth token nor DRIZZA_GITHUB_TOKEN returned a token for the Drizza process. Run gh auth status as the same user, or confirm that the variable was exported in the shell that started Drizza. If you exported the variable after starting Drizza, restart it from that shell.

The GitHub CLI cannot read the keychain

Over SSH or in other non-login sessions, the GitHub CLI may fail to read a token stored in the system keychain. Drizza detects this and suggests the command below. Sign in again with file-based storage:

gh auth login --insecure-storage

This stores the token in the GitHub CLI configuration file instead of the keychain. Alternatively, use DRIZZA_GITHUB_TOKEN.

GitHub refused the token or the search

Check that the token has not expired, that the repositories are in its repository access, and that it has Pull requests: Read-only. If the resource owner is an organization that requires approval, the token stays pending and can only read public resources until an organization owner approves it. Organizations that use SAML single sign-on also require you to authorize the token.

Some pull requests are missing

Check the repository access and resource owner of the token, and the result limit above.
